We are adding inventory tracking to Candy CrackZZZ 8.4.

Do not change Replit startup, workflows, ports, artifact configs, OpenAI, Twilio, Google Maps, payment setup, routing, or unrelated UI.

Focus only on inventory tracking for ingredients, packaging, containers, cups, lids, bags, labels, trays, sticks/skewers, cleaning/food prep supplies, and other items needed to keep on hand.

Goal:
Create an inventory system so admin can track what supplies are on hand, set low-stock alerts, connect inventory items to menu products, and automatically deduct inventory when orders are placed or completed.

Main concept:
Each sellable product should have a “recipe” or “inventory usage list.” When that product is ordered, the system subtracts the required ingredients and packaging from inventory.

Example:
If a customer orders 1 tray of candy grapes, the app may subtract:
- grapes
- sugar/candy mix
- flavoring
- food coloring
- tray container
- lid
- label/sticker
- bag
- fork/pick/skewer if included

If a customer orders a dirty soda, the app may subtract:
- cup size
- lid
- straw
- soda
- syrup/flavor
- creamer
- candy topping

Inventory categories:
- Ingredients
- Candy/coating supplies
- Fruit
- Toppings
- Drinks/soda supplies
- Donutzzz supplies
- Containers
- Cups
- Lids
- Bags
- Labels/stickers
- Utensils/straws/picks
- Cleaning/prep supplies
- Miscellaneous

Part 5 — Inventory deduction rules

Implement deduction logic:

When an order is placed or marked complete:
1. Read the products and quantities in the order.
2. For each product, read its inventory usage list.
3. Multiply inventory usage by order quantity.
4. Subtract from current inventory.
5. Create an inventory transaction record.
6. Prevent duplicate deductions for the same order.
7. Show warning if inventory would go negative.
8. Allow admin override if needed.

Inventory transaction types:
- order_deduction
- manual_adjustment
- restock
- waste/spoilage
- correction
- return/cancel reversal

Each transaction should record:
- id
- inventoryItemId
- orderId optional
- productId optional
- transaction type
- quantity change positive or negative
- previous quantity
- new quantity
- reason/note
- createdAt
- createdBy/admin optional

Important:
Do not deduct twice if the same order is refreshed, edited, or marked complete twice.
