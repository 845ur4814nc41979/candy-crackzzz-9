Step 2 — Add backend-only Google directions endpoint

Add a backend API endpoint so the key stays server-side.

Create or update an endpoint like:

GET /api/cc/directions?origin=...&destination=...

or preferably:

POST /api/cc/directions

Body:
{
  "origin": "business/store address",
  "destination": "customer delivery address"
}

Behavior:
- Read GOOGLE_MAPS_API_KEY from process.env.
- If key is missing, return a clear JSON error and do not crash.
- Validate origin and destination are provided.
- Call Google Directions API or Routes API from the backend only.
- Return normalized JSON:
  {
    "ok": true,
    "distanceText": "...",
    "distanceMeters": 12345,
    "durationText": "...",
    "durationSeconds": 1234,
    "mapsUrl": "https://www.google.com/maps/dir/?api=1&origin=...&destination=...",
    "provider": "google"
  }

If Google returns an error, return:
{
  "ok": false,
  "error": "clear safe error message"
}

Do not return the API key to the frontend.

Step 3 — Google Maps link fallback

Even if the API key is missing or the API request fails, the app should still be able to create a clickable Google Maps directions link:

https://www.google.com/maps/dir/?api=1&origin=ENCODED_ORIGIN&destination=ENCODED_DESTINATION

This fallback does not need the API key.
