We are adding OpenAI API support to Candy CrackZZZ 8.4.

Do not change Replit startup, workflows, ports, artifact configs, Twilio, Google Maps, payment settings, products data, checkout logic, rewardzzz logic, referralzzz logic, or unrelated UI.

Use Replit Secrets only.
Do not hardcode the OpenAI API key.
Do not expose the OpenAI API key to frontend code.
Do not print the OpenAI API key.
Do not commit secrets.

Secret name:
OPENAI_API_KEY

Goal:
Add backend-only OpenAI support for AI-assisted Candy CrackZZZ admin tools.

Use cases:
1. Generate catchy product descriptionzzz from product name, flavor, category, and optional notes.
2. Suggest alternate product namezzz.
3. Generate rewardzzz/referralzzz message text.
4. Generate promo/campaign text.
5. Optional later: AI helper for admin/customer support text.

Use the OpenAI Responses API for new work.

Step 2 — Add OpenAI backend service

Create a backend-only service, for example:

artifacts/api-server/src/lib/openai.ts

Requirements:
- Read process.env.OPENAI_API_KEY.
- If missing, return a safe error and do not crash.
- Use the official openai npm package if already installed. If not installed, add it only to the API server package.
- Use the Responses API.
- Use a configurable model with default:
  gpt-5-mini
  or use an existing low-cost model setting if the repo already has one.
- Keep prompts short and cost-conscious.
- Do not send unnecessary customer PII.
- Add helpful logging without printing the API key.

Step 3 — Add backend endpoints

Add endpoints under /api/cc/ai or similar:

POST /api/cc/ai/product-description

Body:
{
  "productName": "Blue Raspberry Grapes",
  "category": "candy dipped fruit",
  "flavors": ["blue raspberry", "sweet", "crunchy"],
  "notes": "optional admin notes",
  "tone": "fun but not too cheesy"
}

Response:
{
  "ok": true,
  "description": "...",
  "suggestedNames": ["...", "...", "..."]
}

POST /api/cc/ai/promo-message

Body:
{
  "campaignType": "rewardzzz",
  "audience": "customers",
  "offer": "double rewardzzz points this weekend",
  "channel": "sms"
}

Response:
{
  "ok": true,
  "message": "..."
}

POST /api/cc/ai/referral-message

Body:
{
  "type": "customer_referralzzz" or "staff_referralzzz",
  "context": "short description"
}

Response:
{
  "ok": true,
  "message": "..."
}

Safety:
- For SMS messages, keep responses short.
- Do not generate medical, illegal, THC/cannabis, alcohol, or age-restricted marketing text unless the admin explicitly configures a compliant age-gated campaign later.
- Do not include fake discount terms that were not provided.
- Do not invent prices.
- Do not invent availability.
- Return a clear error if the prompt is missing required info.
